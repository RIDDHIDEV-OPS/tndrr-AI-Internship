# Task 1 — LoRA Fine-tuning: English → JSON Extraction

> **Part of:** tndrr AI Internship Assignment  
> **Goal:** Fine-tune a ≤1.5B parameter LLM with LoRA/QLoRA to convert plain-English requests into structured JSON.

---

## Overview

This task demonstrates **Parameter-Efficient Fine-Tuning (PEFT)** using **LoRA** (Low-Rank Adaptation) on **Qwen2.5-0.5B-Instruct**. The model is trained to parse three classes of natural language requests into compact JSON:

| Intent | Example Input | Example Output |
|--------|---------------|----------------|
| `user_profile` | "Create a user named Alice, age 30, email alice@example.com" | `{"intent":"user_profile","name":"Alice","age":30,"email":"alice@example.com"}` |
| `product_search` | "Find red shoes under $50" | `{"intent":"product_search","category":"shoes","color":"red","max_price":50}` |
| `booking` | "Book a table for 2 at 7pm tomorrow" | `{"intent":"booking","type":"restaurant","party_size":2,"time":"19:00","date":"tomorrow"}` |

## Quick Start

### Option A — Google Colab (Recommended)

1. Upload `task1_lora_finetuning.ipynb` to [Google Colab](https://colab.research.google.com/).
2. Set runtime → **T4 GPU** (Runtime → Change runtime type → T4).
3. Run all cells top-to-bottom (`Runtime → Run all`).

The notebook handles all installs, dataset generation, training, and evaluation inline.

### Option B — Local (Linux/WSL with CUDA GPU)

```bash

python -m venv .venv && source .venv/bin/activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Generate dataset
python dataset.py --output_dir ./data --seed 42

# 4. Run evaluation (after training)
python evaluate.py \
    --base_model Qwen/Qwen2.5-0.5B-Instruct \
    --lora_adapter ./lora_adapter \
    --test_file ./data/test.json \
    --output_file ./results/eval_results.json
```

> **Note:** `bitsandbytes` requires Linux + CUDA. On Windows, run inside WSL2 or use Colab.

## Model & Training Config

| Parameter | Value | Rationale |
|-----------|-------|-----------|
| Base model | `Qwen/Qwen2.5-0.5B-Instruct` | ≤1.5B params, strong instruction-following baseline |
| Quantization | 4-bit NF4 (QLoRA) | Fits in ~2GB VRAM; free T4 GPU compatible |
| LoRA rank `r` | 16 | Enough capacity for structured output; keeps adapter small |
| LoRA alpha | 32 | Effective LR scale = alpha/r = 2× |
| Target modules | q_proj, k_proj, v_proj, o_proj | Attention projections capture syntactic structure |
| LoRA dropout | 0.05 | Light regularisation for small dataset |
| Learning rate | 2e-4 | Standard for QLoRA fine-tuning |
| Epochs | 3 | Prevents overfitting on 160-example training set |
| Batch size | 4 | With gradient_checkpointing; fits T4 16GB |
| Optimizer | paged_adamw_8bit | Reduces optimizer memory by ~75% |

## Dataset

Synthetic dataset of **277 examples** generated by `dataset.py`:

| Split | Size | %   | Purpose |
|-------|------|-----|---------|
| Train | 195  | 70.4% | Supervised instruction fine-tuning |
| Val   | 25   | 9.0%  | Model checkpoint selection & validation |
| Test  | 57   | 20.6% | **Held-out evaluation (meets ≥50 examples requirement)** |

Three intent categories balanced across splits: `user_profile` (93 ex.), `product_search` (92 ex.), `booking` (92 ex.)

## Evaluation Metrics

| Metric | Description |
|--------|-------------|
| **Exact Match Accuracy** | Output JSON string semantically identical to target (after normalisation) |
| **Valid JSON Rate** | Fraction of outputs parseable as JSON |
| **Key Accuracy** | Fraction of target keys present in prediction |
| **Value Accuracy** | Fraction of target key-value pairs correctly predicted |

### Expected Results (Qwen2.5-0.5B, T4 GPU, 3 epochs)

| Model | Exact Match | Valid JSON | Key Acc. | Value Acc. |
|-------|-------------|------------|----------|------------|
| Base (no fine-tuning) | ~10–20% | ~60–70% | ~40–55% | ~25–40% |
| Fine-tuned (LoRA) | **~75–90%** | **~95–100%** | **~90–95%** | **~85–92%** |

> Actual numbers will vary; run the notebook to get exact figures.

| Strategy | 7B Model VRAM | Fits on |

## Failure Modes

Three documented failure categories (see Cell 8):

1. **Ambiguous Relative Time** — "this weekend" / "next week" have no canonical JSON representation
2. **Implicit/Inferred Fields** — "book a fancy dinner for two" implies `occasion` but doesn't state it
3. **Multi-value / List Fields** — "find blue and green shoes" → model outputs one color, not an array
